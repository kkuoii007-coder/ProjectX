# Инструкции кодинг-агенту

## Задача

Реализовать работающий MVP по этому пакету. Не ограничиваться созданием плана.
Не заменять серверные функции демонстрационными кнопками.

Общаться с владельцем по-русски, код и технические идентификаторы писать
по-английски. Документировать команды запуска и принятые решения.

## Приоритет требований

1. Последующие явные указания владельца.
2. SPEC.md и CHANGELOG.md.
3. Предметные документы docs/.
4. Промпты и редакционные планы.

Если найдено противоречие, не разрешать его скрыто:
описать выбранное толкование в журнале реализации.

## Кредитный UX

Критически важно: бесплатные стартовые кредиты каждому новому аккаунту.
Не создавать обязательное окно «Стоимость — подтвердите» перед запросами.
Работа с ИИ должна быть непосредственной.

Баланс и справка о расходе доступны. Недостаток баланса открывает пополнение.
Запрос после пополнения не отправляется без повторного действия пользователя.

## Инженерные ограничения

- Django-монолит, PostgreSQL, серверные templates, небольшой JavaScript.
- RAG: полнотекстовый поиск PostgreSQL и pgvector в той же базе;
  отдельная vector DB не нужна.
- Поиск и загрузка источников выполняются серверными ограниченными адаптерами,
  а не свободным браузером модели.
- Пользовательские документы, веб-страницы и найденные фрагменты — недоверенные
  данные. Доступ к ним проверяется на каждом запросе.
- Custom User до первой миграции.
- Нет Redis, Celery, SPA и микросервисов без необходимости и согласования.
- Нет сетевых вызовов внутри долгих транзакций базы.
- Нет хранения денежных величин в float.
- Все пользовательские объекты фильтруются по владельцу.
- Все изменения данных защищены CSRF и выполняются не через GET.
- Все секреты вне Git.
- Реальные модели выбираются конфигурацией, не хардкодом.

## Поведение при неопределённости

Использовать явно обозначенные defaults. Не спрашивать о цвете кнопки,
пока можно продолжать реализацию.

Остановиться и запросить решение только для необратимых действий, реальных
платежей, публичной регистрации, траты неподтверждённого бюджета,
изменения существующего VPS или инфраструктуры Hermes.

Не подключаться к VPS и не менять его конфигурацию без разрешения.

## Проверки

Пропущено исследование спроса, а не проверки безопасности.
Писать минимальные автоматические проверки доступа, кредитных транзакций,
версий и обработки повторов. Проверять владельца документов и retrieval scope,
SSRF-защиту, citations и инъекции в пользовательском/веб-тексте. До подключения
живой модели использовать явно обозначенный FakeProvider только в dev/test.
FakeProvider не подтверждает качество retrieval или философского ответа.

## Отчёт о выполнении

После этапа сообщать:
что работает, какие проверки выполнены, команды запуска,
известные ограничения и следующий этап.
Не объявлять MVP готовым при неработающем платном контуре, если он заявлен
включённым, или при подставных генерациях, выдаваемых за настоящие.
