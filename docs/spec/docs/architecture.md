# Архитектура

## Выбор

Модульный монолит:
Python 3.12, Django 5.2 LTS, PostgreSQL 16 с pgvector,
Django templates, HTMX, небольшой vanilla JavaScript, обычный CSS,
Gunicorn и systemd.

Использовать безопасные patch-релизы и lock-файл.
Django 5.2 — LTS и совместим с Python 3.12.
Источник: [release notes](https://docs.djangoproject.com/en/dev/releases/5.2/).

Это проектный выбор для ограниченного VPS, а не универсальный рейтинг стеков.
Его работоспособность рядом с Hermes проверяется фактически.

## Модули

- accounts: аккаунты, сеансы, экспорт, удаление.
- library: темы, мыслители, подборки, карточки, публикации.
- sources: документы, права, загрузка, веб-поиск, индексация и retrieval.
- workshop: проекты, диалог, ревизии, связи с исходными фрагментами.
- ai: адаптер, задачи, попытки, проверка, repair.
- credits: кошелёк, резервы, начисления, платежи.
- community: следующий этап — предложения, оценки и продвижение.
- operations: жалобы MVP, аудит, лимиты, технические команды.

## Процессы

1. Web обрабатывает короткие запросы.
2. Один AI-worker берёт задачи из PostgreSQL: импорт, embeddings, поиск, fetch,
   генерацию и проверку. Это последовательные управляемые стадии, не автономный агент.
3. Maintenance запускается таймером и проверяет зависшие задачи, сроки хранения
   и бюджетные записи; после MVP — продвижение кандидатов.
4. PostgreSQL хранит состояние, очередь, документы, полнотекстовые индексы и embeddings.

Никаких ИИ-вызовов в HTTP-потоке читалки или внутри транзакции базы.
Перевод и чтение работают при недоступности OpenRouter.

## Очередь

Таблица задач, выборка с блокировкой и пропуском уже захваченных строк,
lease, heartbeat, fencing token и дедупликация.
Одна задача одновременно на аккаунт; один живой worker на старте.

Сетевой таймаут после отправки не доказывает, что провайдер не выполнил вызов.
Exactly-once у внешней модели не обещать.
Локальный учёт и сохранение результата должны быть идемпотентными.

## Интерфейс

HTMX используется как enhancement. Базовые формы и навигация остаются
понятны без него. Статус задач опрашивается, без WebSocket и без
непроверенного streaming текста пользователю.

## Хранение

Публичные страницы рендерятся сервером.
Приватные ответы: Cache-Control private, no-store.
Никакого общего CDN-кэша кабинета.

Не добавлять object storage, Redis, брокер сообщений и отдельную vector DB в MVP.
Использовать PostgreSQL full-text search и pgvector; при необходимости исходные
файлы хранятся в приватном каталоге вне static с контролируемой выдачей.
Локально также использовать PostgreSQL: SQLite не проверяет нужную конкурентность.

Подробный контур источников: [sources-and-rag.md](sources-and-rag.md).
