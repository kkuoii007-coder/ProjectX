# Конвейер ИИ

## Адаптеры

ProviderAdapter: generate_structured, get_usage_if_supported.
Реализации: OpenRouterProvider и явно тестовый FakeProvider.
Генерация, редактирование, вопрос, review и repair используют отдельные
промпты и JSON Schema через общий адаптер.

SearchAdapter ищет источники через настроенный Search API.
DocumentFetcher получает один серверно выбранный URL с ограничениями безопасности.
EmbeddingAdapter индексирует фрагменты; их вызовы учитываются в бюджете владельца.
Все адаптеры вызываются сервером. Модель не получает общий доступ к ним.

Default API: Chat Completions.
Параметры модели, token caps, timeout, provider allowlist и privacy policy —
серверная конфигурация.

Структурированные ответы поддерживаются не всеми endpoints:
использовать response_format json_schema со strict=true, require_parameters=true
и локальную валидацию. Не молчаливо переходить на несовместимый endpoint:
соответствие зависит от конкретного endpoint даже при structured outputs. Источник:
[OpenRouter](https://openrouter.ai/docs/guides/features/structured-outputs).

Настройки retention не равны абсолютному отсутствию правовых исключений.
Не обещать пользователю «никто нигде не хранит запрос».
Источник: [OpenRouter ZDR](https://www.openrouter.ai/docs/guides/features/zdr).

## Подготовка источников

Для simplify_source пользователь выбирает свой готовый документ и область.
Для explain_topic сервер ищет локальные карточки и разрешённые документы.
При недостатке опоры генерация завершается needs_clarification без списания и ссылки
на модель. Пользователь запускает отдельный ограниченный поиск, выбирает документ,
дожидается его сохранения и индексации, затем явно повторяет генерацию. AIJob не
остаётся в ожидании выбора и не продолжается автоматически после импорта.
Произвольный URL модели не скачивается. Правила: [источники и RAG](sources-and-rag.md).

## Генерация и упрощение

1. Проверить режим, владельца, тему, длину и допустимость запроса.
2. Зафиксировать версии документов и карточек, получить ограниченный набор chunks.
3. Сгенерировать серию с парами en/ru, glossary и evidence либо вернуть уточнение/отказ.
4. Проверить структуру, citation_id, численные ограничения и область источника.
5. Выполнить отдельный reviewer.
6. При исправимой содержательной ошибке — одна repair-попытка отдельным промптом.
7. Повторить review и сохранить результат с evidence.

Максимум четыре generation/review вызова: generate/edit → review → repair → review.
Retrieval, search/fetch и embeddings — отдельные ограниченные операции, а не скрытые
повторы генерации. Поиск и импорт выполняются отдельными AIJob и не увеличивают лимит
вызовов generate/edit. Если repair не нужен, лишних вызовов нет. Невалидный JSON — сбой,
а не повод запускать новый цикл. Timeout после отправки не повторяется автоматически.
outcome=delivered ставится только после сохранения полезного ответа или ревизии,
прошедшей допустимый для сценария финальный review. Неисправимый кандидат и повторный
review=fail завершаются без списания; техническая ошибка не маскируется под refusal.

## Форматы ответов

GenerationResult: outcome series/needs_clarification/refused.
EditResult: outcome edited/needs_broader_edit/needs_clarification/refused.
AskResult: outcome answered/needs_clarification/refused.
ReviewResult: verdict pass/repair/fail, factual_state supported/mixed/unsupported/
unverified и структурированные issues.

При outcome=series:
schema_version: "2"
title_en, title_ru: string
parts: ordered array из 3–5 объектов
part: title_en, sentences, source_chunk_citation_ids для simplify_source
sentence: en, ru
glossary: term_en, explanation_en, translation_ru
simplification_note_ru: string
claims: claim_text, part_ordinal, sentence_ordinal, citation_ids, fact_ids,
support_type quotation/paraphrase/interpretation.
source_chunk_citation_ids связывают каждую часть с исходными диапазонами;
claims описывают поддержку утверждений и не заменяют эту связь.

Сервер создаёт UUID, ключи частей/предложений и content hash. Модель не возвращает
knowledge_card_ids, document UUID, target, права, публикацию, модель или кредиты.
citation_id относится только к фактически переданным RetrievalItem; fact_id — только
к разрешённым версиям карточек. Учебный пример без внешнего утверждения не требует
искусственной ссылки; важное философское утверждение без опоры не выдаётся за факт.

Все обязательные поля перечислены в JSON Schema, additionalProperties=false,
длины строк и массивов ограничены. Для неуспешных исходов есть короткое message_ru
и при необходимости clarification_question_ru. Они не содержат исполняемой разметки.

## Правки

Для sentence/part сервер передаёт выбранный фрагмент, ограниченный соседний контекст
и необходимые evidence. Модель возвращает содержимое замены, не target, не ключи
технических объектов и не произвольный JSON Patch.

Для sentence допустимы одно или два предложения en/ru; заголовки и glossary не
меняются. Для part возвращается только содержимое части. Сервер собирает новый
снимок, сравнивает его с исходным и отклоняет любой выход за разрешённую область.
Неизменённые предложения, переводы и evidence копируются сервером без пересоздания.
Изменённые предложения получают согласованный перевод и новые проверенные evidence.

Результат — новая ревизия, но head меняется только после «Применить».
Создание первой успешной серии устанавливает head автоматически.

## Вопросы

ask использует [answering.md](../prompts/answering.md) и один внешний generation-вызов без скрытого
reviewer/repair. Он возвращает русское объяснение по переданным фрагментам, не меняет
ревизию и не утверждает, что прочитан весь документ, если получены только chunks.
Вопрос о тексте не равен команде изменить его. Можно предложить режим «Изменить»,
но не переключать его автоматически. При недостатке evidence ответ ограничивается.

## Допуск к публикации

Не модель выставляет publication=true. В MVP администратор отдельным действием
создаёт editorial Publication для конкретной ревизии. Сервер требует quality report
для текущего content hash, проверенную карточку, покрытые ключевые утверждения,
допустимые права на источники и явное действие администратора. Это не обход будущего
голосования, а отдельный маркированный редакционный путь.

Для темы без карточки допускается приватный результат по источникам со статусом
«Черновик: фактическая опора ещё не проверена». При отсутствии достаточных источников
сервер возвращает needs_clarification или refused без списания, а не выдуманный
уверенный текст. «Ограниченный ответ» не является отдельным GenerationResult outcome.
Карточка не подбирается только по совпадению имени; пользовательский текст не
становится редакционным источником автоматически. Если sources есть, а проверенной
карточки нет, reviewer оставляет factual_state=unverified; verdict=pass сам по себе
не даёт publication_eligibility=eligible. При грубом несоответствии источникам
результат отклоняется, а не сохраняется как полезный непроверенный черновик.

## Безопасность

Недоверенные данные: пользовательский ввод, документы, веб-страницы, история,
прошлые ответы модели, цитаты карточек и issues, переданные в repair. Разделение
сообщений и разметка помогают, но не являются достаточной защитой.

Сервер задаёт operation, target, scope и модель; проверяет владельца, схему, длину,
citation/fact IDs и diff. Модель не получает shell, общий браузер, секреты, Hermes,
инструменты публикации, кредитов или выбора endpoint. Search/fetch/embeddings —
отдельные серверные адаптеры с лимитами, а не свободные вызовы модели.

HTML ответа экранируется, Markdown/JavaScript не исполняются. Даже вредоносный
валидный JSON не должен привести к действию вне разрешённой области. Не обещать
полной защиты от инъекций; мера безопасности — отсутствие запрещённого эффекта.

Prompt version, schema version, model, provider, usage, source/retrieval hashes и
технические исходы сохраняются. Сырые prompts, документы и диалоги не пишутся
в общесистемные логи. Adversarial-проверки обязательны: [приёмка](acceptance.md).
