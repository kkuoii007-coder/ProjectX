# Готовое задание кодинг-агенту

## Сообщение для запуска

Прочитай README.md, SPEC.md, AGENTS.md и IMPLEMENTATION_START.md.
Создай рабочий MVP Philosophy Reader по всему пакету.

Это интеллектуальный журнал для чтения философии на максимально простом
английском, с русским переводом предложений, личной ИИ-мастерской, загрузкой
своих текстов, ограниченным поиском источников, RAG и версиями.
Голосование — следующий этап, не часть MVP.

Сначала работай локально. Исходники затем пойдут в частный Git.
VPS существует, но не подключайся и не меняй его без разрешения.

Каждому новому пользователю автоматически начисляй бесплатные кредиты.
Не добавляй обязательное подтверждение стоимости перед каждым запросом.
При нехватке сохраняй ввод и показывай пополнение.
Серверный учёт, лимиты и защита бюджета обязательны.

Восстановления доступа нет. Регистрация только по логину и паролю,
с крупным предупреждением о необходимости сохранить их.

Стек по умолчанию: Django-монолит, PostgreSQL с pgvector, templates, HTMX,
один фоновый AI-worker, OpenRouter через серверный адаптер. Используй
[sources-and-rag.md](sources-and-rag.md): локальный retrieval, серверный поиск и ограниченный fetch;
не давай модели свободный браузер или произвольные инструменты.

Не проводи предварительное исследование спроса.
Реализуй MVP и минимальные технические проверки вместе с функциями.
FakeProvider допустим только для dev/test; production не должен маскировать
ошибки модели заранее приготовленными ответами.

Следуй [implementation-plan.md](implementation-plan.md) и [acceptance.md](acceptance.md).
Не останавливайся на плане или красивом frontend.
Если нет ключа или бюджета, реализуй весь контур и сообщи, что нужно настроить
для живого вызова. Чтение и локальные сценарии должны работать.

Реальные продажи отключены до настройки провайдера и условий.
Не выдумывай юридические реквизиты и не обещай отсутствие персональных данных.

После каждого законченного этапа перечисляй:
работающие сценарии, выполненные проверки, команды запуска и ограничения.

## Итоговая передача

Нужны исходники, миграции, seed-команда, тесты,
.env.example, lock-файл, локальная установка,
worker и maintenance, deployment и backup инструкции.

Не заявляй «готово», пока критические сценарии не проверены.
Оставшиеся условия публичного запуска перечисли отдельно от недоделок кода.
