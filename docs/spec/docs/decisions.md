# Реестр решений

## Подтверждено владельцем

Английские философские тексты с максимальной простотой,
маленькие части, перевод предложения по нажатию,
интеллектуальный журнал, личная работа с ИИ,
фрагментарная перегенерация, загрузка своего текста,
локальные источники и RAG, ограниченный серверный веб-поиск,
библиотека через высокие оценки следующим этапом,
логин/пароль без восстановления,
бесплатные кредиты новичкам, предложение пополнения после расхода,
локальная разработка и последующее размещение,
сохранение технических проверок.

## Принятые defaults

| Решение | Основание и последствия |
|---|---|
| Django-монолит | Меньше отдельных компонентов; встроенная административная часть |
| PostgreSQL + pgvector | Транзакции, очередь, FTS и embeddings без новой СУБД |
| Серверный поиск + RAG | Воспроизводимые источники вместо свободного браузера |
| Выбор нового веб-источника пользователем/admin | Нет автономного обхода сайтов |
| Сообщество после MVP | Приоритет качеству источников и основному циклу |
| Templates + HTMX | Не нужна отдельная SPA |
| 30 стартовых кредитов | Конфигурируемый тестовый объём, не финансовая оценка |
| Нет ежедневного гранта | Снижает неограниченные обязательства владельца |
| Manual test top-up | Продажи не выдумываются без провайдера |
| 3–5 частей | Постепенное раскрытие идеи |
| Карточка для публикации | Ограничение качества, замедляющее расширение тем |
| Голоса 10/4.5/80%/72ч | Исходная настройка для последующей корректировки |
| Один AI-worker | Осторожный старт на ограниченном сервере |
| RU interface | Соответствует текущему запросу и переводу |

Defaults можно менять с обновлением документов и конфигурации.
Карточки знаний — предлагаемое ограничение этого пакета, не утверждение,
что владелец специально заказал ручное утверждение всех текстов.

## Важные компромиссы

Открытые аккаунты без email означают ограниченную защиту от накрутки и
повторного получения стартовых кредитов через новые аккаунты.

Отсутствие восстановления упрощает аккаунт, но увеличивает риск потери
купленного остатка и требует особенно аккуратного платёжного запуска.

Строгая простота не гарантирует, что любая философская тема полностью
выразима на A1. Допускаются серии и явное объяснение упрощений.

Модели помогают проверять качество, но не являются независимой экспертизой.
RAG повышает проверяемость, но не гарантирует релевантность, полноту и верность вывода.
Веб-поиск добавляет риски SSRF, инъекций, прав и расходов; поэтому свободный браузер
не используется, найденный источник выбирается человеком и сохраняется до генерации.
Полнотекстовое хранение энциклопедий требует отдельной проверки условий; ссылка и
право копирования не эквивалентны.

## Решает владелец перед включением

- Публичный бренд и домен.
- Юридический статус, аудитория и фактическое размещение данных.
- Денежный дневной и месячный бюджет.
- Конкретные endpoints генерации, проверки и embeddings.
- Search API, доменный allowlist и разрешённые правила получения документов.
- Права хранения и обработки начального корпуса и энциклопедических материалов.
- Доступный запас ресурсов рядом с Hermes.
- Открытая или приглашённая регистрация.
- Продавец, провайдер, валюта и пакеты, если включаются продажи.

Агент может писать код без этих ответов, сохраняя опасные режимы выключенными.
