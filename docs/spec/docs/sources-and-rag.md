# Источники, веб-поиск и RAG

## Назначение

Сервис опирается не только на параметрические знания модели. У результата должны
быть сохранённые и проверяемые источники. RAG дополняет модель, но не доказывает
философскую точность сам по себе.

Три разных вида материала не смешиваются по уровню доверия:

- пользовательский документ — приватный материал для работы владельца;
- редакционный источник — сохранённый документ с проверенными метаданными и правами;
- найденный веб-источник — кандидат, который не становится проверенным автоматически.

## Режимы использования

### Упростить свой текст

Пользователь вставляет текст или загружает TXT, Markdown либо PDF с текстовым
слоем. Он выбирает конкретный фрагмент или документ и режим «Упростить».
Исходный текст — главный предмет работы. Дополнительные источники могут
пояснять понятия, но не заменяют и не исправляют позицию автора молча.

Результат сохраняет связь с исходными фрагментами. Для последовательного
упрощения короткого фрагмента модель получает его целиком. Для длинного документа
RAG используется при выборе фрагментов и ответах на вопросы. Если выбранная область
не помещается в лимит контекста, сервер предлагает выбрать раздел и возвращает
needs_clarification без списания, а не выдаёт краткий retrieval за полное упрощение.

### Объяснить тему

Сервер сначала ищет разрешённые локальные источники и карточки. Если их
недостаточно, generation job возвращает needs_clarification и предлагает поиск.
Поиск, выбор, импорт и индексация — отдельные операции; после их завершения
пользователь повторно запускает генерацию. Новый веб-документ выбирает пользователь
или администратор; автономного обхода сайтов моделью нет.

### Спросить по тексту

Модель получает только найденные фрагменты, а не утверждает, что прочитала весь
документ. Она различает содержание источника, собственный вывод и неизвестное.
Ответ не изменяет ревизию.

## Импорт и индексация

1. Проверить владельца, тип, размер, квоту и допустимость документа.
2. Для пользовательского файла — извлечь текст без выполнения активного содержимого.
3. Для веб-источника — получить один серверно выбранный документ с ограничениями.
4. Сохранить исходный объект при необходимости, нормализованный текст, hash,
   метаданные, права и provenance.
5. Разбить текст по разделам и абзацам, сохранив страницы и позиции, если доступны.
6. Создать полнотекстовый индекс PostgreSQL и embeddings через pgvector.
7. Пометить документ ready только после завершения обязательных проверок.

Default для настройки после измерений: фрагмент 300–600 английских слов с небольшим
перекрытием. Не разрывать предложение и не объединять несвязанные разделы ради
фиксированного размера. Повтор hash не создаёт вторую версию документа.

PDF без текстового слоя отклоняется с понятной причиной. OCR, DOCX, EPUB,
распознавание изображений и массовый импорт библиотек не входят в MVP.

## Поиск и выдача контекста

1. Сервер задаёт scope: документ владельца, редакционный корпус или выбранные источники.
2. Полнотекстовый и векторный поиск выполняются только внутри этого scope.
3. Результаты объединяются простым детерминированным правилом, дубли устраняются.
4. Ограниченное число фрагментов получает временные citation_id действия.
5. Модель ссылается на citation_id, но не назначает права, статусы и URL сама.
6. Сервер проверяет соответствие citation_id фактически переданным фрагментам.
7. Reviewer проверяет смысловую поддержку утверждения, а не только наличие ссылки.

Не добавлять reranker, Knowledge Graph, GraphRAG и иерархические summaries в MVP.
Качество retrieval проверяется на примерах до увеличения корпуса.

## Веб-поиск

SearchAdapter вызывает выбранный Search API по серверному запросу. Начальный
allowlist содержит согласованные философские энциклопедии, университетские
хранилища и собрания первичных текстов. Он снижает шум, но не гарантирует качество,
отсутствие инъекций или право хранения текста.

DocumentFetcher:

- принимает только разрешённые http/https URL после нормализации;
- запрещает loopback, private/link-local IP, внутренние имена и cloud metadata;
- повторно проверяет DNS и каждый redirect, включая защиту от DNS rebinding;
- ограничивает redirects, время, размер, тип содержимого и число документов;
- не исполняет JavaScript, не передаёт cookies и секреты;
- учитывает robots.txt, условия сайта и ограничения automated access;
- не обходит технические ограничения и не сканирует весь сайт.

Search, fetch, embeddings и генерация выполняются worker-процессом вне транзакции БД.
Перед каждым внешним вызовом сохраняются SourceAttempt или ProviderAttempt и
request_hash; новый stage_number не перезаписывает неопределённую попытку.
Неопределённый fetch не повторяется автоматически по тому же URL. После ответа
сохраняются hash и provenance. Это не гарантирует exactly-once у внешнего сервиса.

Результат поиска сохраняется до его использования, чтобы генерацию можно было
воспроизвести по конкретной версии источника.

## Права и атрибуция

Свободный доступ для чтения не означает разрешение на копирование, индексацию,
создание производных материалов и публичное распространение. Права фиксируются
отдельно для хранения, обработки, цитирования и публикации. При неопределённости
документ остаётся приватным либо используется только как внешняя ссылка до решения
владельца и необходимой правовой проверки.

- SEP: [условия использования](https://plato.stanford.edu/info.html) содержат
  ограничения распространения и коммерческого признака.
- IEP: [copyright](https://iep.utm.edu/home/copyright/) не относит статьи к public
  domain и ограничивает их размещение на других сайтах.
- Project Gutenberg: [условия](https://www.gutenberg.org/policy/terms_of_use.html)
  не гарантируют статус public domain за пределами США. Старое произведение и
  современный перевод имеют разные права.

Не выдавать этот список за юридическое заключение. До проверки энциклопедии не
копируются массово в полнотекстовый корпус: предпочтительны ссылки, разрешённые
короткие цитаты и проверенные собственные карточки.

## Стартовый корпус

Для MVP достаточно 3–5 первичных текстов и связанных с ними проверенных материалов
по стартовым темам. Массовый scraping энциклопедий не требуется. Каждая запись
имеет вид работы, издание/перевод, автора, язык, источник получения, дату, hash,
права, статус проверки и историю версий.

## Безопасность и приватность

Любой документ может содержать prompt injection. Текст документа — недоверенные
данные даже при авторитетном домене. Он не получает инструментов и не может изменить
системные правила, область поиска, чужие документы, публикацию или списания.

Пользовательские документы и их embeddings недоступны другим аккаунтам, не входят
в редакционный корпус и не публикуются вместе с производным текстом автоматически.
Перед публикацией отдельно проверяются права на исходник и объём цитирования.

При удалении документа или аккаунта удаляются его документы, chunks, embeddings
и приватные evidence. История ревизий сохраняет безопасные provenance-метаданные,
но не текст удалённого источника. Ревизия, использующая его, остаётся приватной
и не может быть опубликована: требуемые evidence и права больше недоступны.
Исключаются только минимальные записи, которые владелец обязан сохранить.
Если источник используется публикацией, сначала требуется снять её с публикации
или запретить удаление до отдельного редакционного решения; нельзя оставлять
публичный материал с удалённой доказательной базой. Удаление аккаунта удаляет
его приватные ревизии целиком, включая производные тексты.
